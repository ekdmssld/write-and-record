# Write & Record - QA and Beta Test Plan

목적: 친구 테스트 전에, 이 앱의 핵심 가치인 "하루하루를 기록하고 확인할 수 있음"을 검증한다.

테스트의 중심 질문:
- 첫 기록을 쉽게 남길 수 있는가?
- 날짜별로 기록을 다시 찾을 수 있는가?
- 저장한 기록이 사라지지 않는가?
- 사진 권한이 없어도 앱이 쓸 만한가?
- 친구가 설명 없이도 기본 흐름을 이해하는가?

## 1. QA Priority

가장 먼저 검증:
1. 앱 실행.
2. 온보딩 완료.
3. 오늘 날짜 기록 저장.
4. 다른 날짜 기록 저장.
5. 캘린더에서 기록 확인.
6. 상세 보기.
7. 수정.
8. 삭제.
9. 앱 재실행 후 데이터 유지.
10. JSON export.

후순위:
- 카드 디자인.
- 고급 검색.
- 지도.
- 친구 기능.
- AI.
- 세밀한 카테고리 템플릿.

## 2. Test Phases

### Phase 0: Developer Smoke Test

대상:
- 개발 중 매 빌드.

목표:
- 앱이 켜지고 핵심 플로우가 깨지지 않는지 확인.

소요:
- 10~15분.

통과 기준:
- 새 기록 저장 가능.
- 캘린더에 기록 표시.
- 상세 진입 가능.
- 앱 재실행 후 기록 유지.

### Phase 1: Personal 7-Day Test

대상:
- 본인 iPhone.

목표:
- 실제 생활 기록으로 7일 동안 쓸 수 있는지 확인.

규칙:
- 하루 최소 1개 기록.
- 사진 없는 기록도 남긴다.
- 과거 날짜 기록도 1개 이상 남긴다.
- 긴 본문 기록을 1개 이상 남긴다.
- 앱을 하루에 여러 번 껐다 켠다.
- 7일차에 JSON export를 만든다.

통과 기준:
- 7일 동안 데이터 유실 없음.
- 기록 작성이 귀찮아서 포기할 정도로 무겁지 않음.
- 캘린더에서 기록 있는 날을 바로 알아볼 수 있음.

### Phase 2: Close Friend Guided Test

대상:
- 가까운 친구 1~2명.

목표:
- 설명을 조금만 듣고도 핵심 흐름을 완료하는지 확인.

방식:
- 직접 옆에서 설치/실행을 도와도 된다.
- 테스트 중 막히는 지점을 메모한다.
- 친구가 작성한 사적인 기록 내용은 수집하지 않는다.

통과 기준:
- 친구가 첫 기록을 저장한다.
- 친구가 어제/오늘 기록을 다시 찾는다.
- 친구가 "어디 눌러야 할지 모르겠다"는 지점이 2개 이하.

### Phase 3: TestFlight Beta

대상:
- 친구 3명 이상.

조건:
- Phase 1에서 데이터 유실이 없어야 한다.
- export가 가능해야 한다.
- PersonalRelease에서 debug UI가 숨겨져야 한다.

목표:
- 각자 기기에서 설치/사용/피드백이 가능한지 확인.

통과 기준:
- 설치 실패가 드묾.
- 첫 기록 완료율이 높음.
- 심각한 저장 실패 없음.

## 3. Core Smoke Checklist

매 빌드에서 확인:

- [ ] 신규 설치 후 앱 실행.
- [ ] 온보딩 완료.
- [ ] 오늘 날짜 선택.
- [ ] 카테고리 선택.
- [ ] 제목만 입력하고 저장.
- [ ] 본문 포함 기록 저장.
- [ ] 기록 상세 보기.
- [ ] 기록 수정.
- [ ] 기록 삭제.
- [ ] 앱 종료 후 재실행.
- [ ] 저장한 기록 유지 확인.
- [ ] 사진 권한 거부 후 기록 저장.
- [ ] JSON export 생성.

## 4. Daily Record Test Cases

### Basic Create

절차:
1. 캘린더에서 오늘 선택.
2. 기록 추가.
3. 기본 카테고리 선택.
4. 제목 입력.
5. 저장.

기대 결과:
- EntryDetail로 이동한다.
- 캘린더로 돌아가면 오늘 날짜에 기록 표시가 있다.

### Past Date Create

절차:
1. 어제 날짜 선택.
2. 기록 추가.
3. 제목/본문 저장.

기대 결과:
- 어제 날짜에 기록이 표시된다.
- 오늘 날짜에는 잘못 표시되지 않는다.

### Multiple Entries Same Day

절차:
1. 같은 날짜에 기록 3개 저장.
2. 캘린더에서 해당 날짜 선택.

기대 결과:
- 그날 기록 목록에 3개가 보인다.
- 카테고리 색 점은 최대 표시 규칙을 지킨다.

### Long Text

절차:
1. 제목 80자 근처.
2. 본문 3,000자 이상.
3. 저장 후 상세 보기.

기대 결과:
- 저장 가능.
- 상세 화면에서 레이아웃이 깨지지 않는다.
- 수정 화면 재진입 시 텍스트가 유지된다.

### Draft Recovery

절차:
1. 기록 작성 중 제목/본문 입력.
2. 저장하지 않고 앱을 종료.
3. 앱 재실행.

기대 결과:
- draft 복구 안내 또는 자동 복구가 동작한다.
- 입력한 내용이 사라지지 않는다.

### Photo Permission Denied

절차:
1. 사진 추가 시 권한 거부.
2. 제목/본문만 저장.

기대 결과:
- 사진 없이 저장 가능.
- 권한 거부가 앱 사용 차단으로 이어지지 않는다.

## 5. Data Safety Checklist

반드시 통과:
- [ ] 앱 재실행 후 entries 유지.
- [ ] 앱 강제 종료 후 저장된 entries 유지.
- [ ] draft가 저장 실패 후 유지.
- [ ] 삭제는 confirm 후 실행.
- [ ] 삭제된 기록은 기본 목록에서 사라짐.
- [ ] export JSON에 entries/categories/profile 포함.
- [ ] export 파일에 schemaVersion 포함.
- [ ] export 중 오류가 나면 사용자에게 알려줌.
- [ ] debug log에 기록 제목/본문이 출력되지 않음.

## 6. Device and Permission Matrix

최소 기기:
- 작은 화면: iPhone SE 계열 또는 작은 simulator.
- 일반 화면: 기본 iPhone.
- 큰 화면: Pro Max 계열.

권한 상태:
- Photos authorized.
- Photos limited.
- Photos denied.
- Notifications off.
- Notifications on.

환경:
- 라이트 모드.
- 다크 모드 optional.
- Dynamic Type large.
- 오프라인 상태.

## 7. Friend Tester Script

친구에게 줄 짧은 안내:

```text
테스트 목표는 예쁜 기능보다 "하루 기록이 잘 저장되고 다시 보이는지" 확인하는 거야.

해볼 것:
1. 온보딩 끝내기
2. 오늘 기록 하나 쓰기
3. 어제 날짜로 기록 하나 쓰기
4. 앱 껐다 켜서 기록이 남아있는지 보기
5. 기록 하나 수정해보기
6. 사진 권한을 거부해도 기록이 되는지 보기

사적인 기록 내용은 보내지 않아도 돼.
막힌 화면, 헷갈린 버튼, 저장이 안 된 순간만 알려줘.
```

## 9. Beta Release Gate

TestFlight 전에 반드시:
- [ ] 7일 개인 테스트 완료.
- [ ] 데이터 유실 0건.
- [ ] 저장 실패 시 draft 유지.
- [ ] 사진 권한 없이 기록 가능.
- [ ] JSON export 가능.
- [ ] mock/debug UI 숨김.
- [ ] 앱 아이콘/launch screen 임시 버전 있음.
- [ ] 피드백 보내기 경로 있음.
- [ ] 개인정보 민감 로그 없음.

TestFlight를 미룰 조건:
- 기록이 사라지는 버그.
- 저장 성공처럼 보였는데 실제 저장되지 않는 버그.
- 앱 재실행 후 캘린더가 비는 버그.
- 사진 권한 거부 시 앱 진행 불가.
- export가 전혀 없음.

## 10. What Not To Optimize Yet

초기 QA에서 깊게 보지 않을 것:
- 카드 템플릿의 미세한 디자인.
- 친구 피드 UX.
- 지도 표현.
- AI 태그 정확도.
- 모든 카테고리별 세부 필드.
- App Store 검색 키워드.

이유:
- 핵심 기록 루프가 안정되기 전에 부가 기능을 다듬으면, 실제 앱의 중심 문제가 늦게 발견된다.

## 11. Success Metrics

정량:
- 첫 기록 완료 시간 3분 이하.
- 기록 저장 성공률 99% 이상.
- 7일 개인 테스트 데이터 유실 0건.
- 앱 재실행 후 기록 복구 성공 100%.
- 친구 테스트 첫 기록 완료율 80% 이상.

정성:
- "오늘 뭐 썼는지 다시 찾기 쉽다."
- "사진 없어도 기록할 수 있다."
- "기록이 사라질까 봐 불안하지 않다."
- "기능이 많지 않아도 매일 쓸 수 있을 것 같다."

## 12. Final Principle

QA의 목적은 버그를 많이 찾는 것이 아니라, 이 앱이 매일 믿고 쓸 수 있는 기록장이 되는지 확인하는 것이다.
